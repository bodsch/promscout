# Grafana dashboard

`promscout.json` shows discovery cycles (age, duration, started/skipped),
the discovered and validated targets, and process and Go runtime health.

It is generated by `generate.py`. Change the script and run
`make dashboards`; an edit to the JSON is lost on the next run.

Import it under *Dashboards → New → Import*. It asks for a Prometheus data
source and offers an `instance` variable, filled from
`promscout_build_info`. `go_*` and `process_*` panels are joined on
`promscout_build_info` by `(job, instance)`, so they show PromScout only —
not every other Go exporter on the same host.

## Thresholds

The README defines no alert rules. The thresholds follow `config.example`
(`interval: 1m`): *Last completed cycle* turns orange after 5 min and red
after 15 min. With a longer `interval`, change `INTERVAL_S` in
`generate.py` and regenerate.

## Before trusting the CPU panel

Check that every scraped process has its own `(job, instance)`:

```promql
count by (job, instance) (process_cpu_seconds_total)
```

If several processes share one pair — typically because `instance` was
relabeled to a host name without a port — their counters are merged into one
series, and `rate()` reads every switch between them as a counter reset. CPU
above 100 % for an idle service is the usual symptom. No dashboard can fix
that; the scrape config has to keep the targets apart.
